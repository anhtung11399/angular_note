Đa ngôn ngữ và PWA

i18n có sẵn của Angular, Transloco, định dạng ngày số tiền theo vùng, service worker và PWA, cập nhật phiên bản mới.

Học xong bài này bạn sẽ:
  • Làm ứng dụng nhiều ngôn ngữ
  • Định dạng ngày, số, tiền đúng vùng
  • Biến ứng dụng thành PWA và xử lý cập nhật

#Định dạng theo vùng (locale)

Trước cả chuyện dịch chữ: ngày, số, tiền phải hiển thị đúng kiểu Việt Nam. Đăng ký locale một lần (bài 8):

app.config.ts
registerLocaleData(localeVi);
providers: [{ provide: LOCALE_ID, useValue: 'vi' }, { provide: DEFAULT_CURRENCY_CODE, useValue: 'VND' }]
TemplateKết quả (vi)
{{ 1234567.5 | number }}1.234.567,5
{{ 49000 | currency }}49.000 ₫
{{ 0.833 | percent: '1.0-1' }}83,3%
{{ d | date: 'fullDate' }}Thứ Tư, 4 tháng 11, 2026
{{ d | date: 'dd/MM/yyyy HH:mm' }}04/11/2026 14:30
{{ d | date: 'HH:mm' : '+0700' }}giờ theo múi giờ chỉ định

Ngày dạng chuỗi '2026-11-10' (không có giờ) được JavaScript hiểu là nửa đêm UTC, hiển thị ở Việt Nam vẫn đúng ngày (7 giờ sáng). Nhưng ở múi giờ âm (Mỹ) sẽ lùi một ngày. Với ngày thuần (hạn nộp, ngày sinh), hiển thị bằng cách tách chuỗi hoặc truyền múi giờ 'UTC' vào pipe.

Báo có phiên bản mới

core/update-banner.ts
@Component({
  selector: 'app-update-banner',
  template: `
    @if (ready()) {
      <div class="banner">Đã có phiên bản mới. <button (click)="reload()">Tải lại</button></div>
    }
  `,
})
export class UpdateBanner {
  private sw = inject(SwUpdate);
  protected ready = signal(false);

  constructor() {
    if (!this.sw.isEnabled) return;
    this.sw.versionUpdates
      .pipe(filter((e) => e.type === 'VERSION_READY'), takeUntilDestroyed())
      .subscribe(() => this.ready.set(true));
    this.sw.unrecoverable.pipe(takeUntilDestroyed()).subscribe(() => location.reload());
  }

  protected async reload() {
    await this.sw.activateUpdate();
    location.reload();
  }
}

Đã có phiên bản mới.

Service worker cache mạnh tay: sau khi deploy, người dùng có thể vẫn chạy bản cũ cho tới khi tải lại. Luôn có thông báo "phiên bản mới" như trên, và xử lý trường hợp chunk JS của bản cũ không còn trên server (lỗi tải chunk sau deploy) bằng cách tự tải lại trang một lần.

Thông báo đẩy (Web Push) dùng SwPush: requestSubscription({ serverPublicKey }) rồi gửi subscription lên server. Trên iPhone, Web Push chỉ hoạt động khi người dùng đã "Thêm vào màn hình chính".

Câu hỏi nhanh. Ứng dụng cần đổi ngôn ngữ ngay khi người dùng chọn, không tải lại trang. Chọn gì?

i18n có sẵn của Angular dịch lúc build, mỗi ngôn ngữ một bản build, đổi ngôn ngữ là chuyển sang bản khác.

Câu hỏi nhanh. dataGroups strategy 'freshness' với timeout 3s nghĩa là gì?

freshness ưu tiên dữ liệu mới, cache là phương án dự phòng.

#Bài tập

Ứng dụng xem lịch học dùng được khi mất mạng

Biến ứng dụng thành PWA: trang lịch học (/api/schedule) vẫn xem được bản gần nhất khi mất mạng, hiện dải "Bạn đang xem bản lưu lúc HH:mm" khi offline, và hiện thông báo khi có phiên bản mới.

Gợi ý từng bước

  1. ng add @angular/pwa, thêm dataGroups freshness cho /api/schedule.
  2. Theo dõi trạng thái mạng: host: { '(window:online)': ..., '(window:offline)': ... } và signal offline.
  3. Lưu thời điểm tải thành công gần nhất vào localStorage (qua service an toàn).
  4. Thử: ng build rồi phục vụ thư mục build bằng npx http-server -p 8080 (service worker không chạy với ng serve), tắt mạng trong DevTools.
Xem lời giải
ngsw-config.json (thêm)
"dataGroups": [
  { "name": "schedule", "urls": ["/api/schedule*"], "cacheConfig": { "strategy": "freshness", "maxSize": 20, "maxAge": "7d", "timeout": "4s" } }
]
schedule-page.ts
@Component({
  selector: 'app-schedule-page',
  imports: [DatePipe, UpdateBanner],
  host: { '(window:online)': 'offline.set(false)', '(window:offline)': 'offline.set(true)' },
  template: `
    <app-update-banner />
    @if (offline()) {
      <p class="offline">Bạn đang xem bản lưu lúc {{ savedAt() | date: 'HH:mm dd/MM' }}</p>
    }
    @for (d of schedule.value() ?? []; track d.date) {
      <h3>{{ d.date | date: 'EEEE dd/MM' }}</h3>
      <ul>@for (p of d.periods; track p.no) { <li>Tiết {{ p.no }}: {{ p.subject }}</li> }</ul>
    }
  `,
})
export class SchedulePage {
  private storage = inject(Storage);
  protected offline = signal(false);
  protected savedAt = signal(Number(this.storage.get('schedule-at') ?? 0));
  protected schedule = httpResource<{ date: string; periods: { no: number; subject: string }[] }[]>(() => '/api/schedule');

  constructor() {
    afterNextRender(() => this.offline.set(!navigator.onLine));
    effect(() => {
      if (this.schedule.hasValue() && !this.offline()) {
        const now = Date.now();
        this.storage.set('schedule-at', String(now));
        untracked(() => this.savedAt.set(now));
      }
    });
  }
}

Giải thích: khi mất mạng, service worker trả bản /api/schedule đã cache sau 4 giây chờ (hoặc ngay nếu trình duyệt biết đang offline), nên httpResource vẫn nhận dữ liệu. Thời điểm lưu chỉ cập nhật khi tải thành công lúc có mạng. navigator.onLine đọc trong afterNextRender để an toàn khi có SSR. Service worker chỉ bật ở bản build production, không chạy với ng serve.
