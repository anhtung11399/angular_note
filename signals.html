Signals: reactivity của Angular

signal, computed, effect, linkedSignal, untracked. Đối chiếu với ref, computed, watch / watchEffect của Vue, và những bẫy hay gặp.

Học xong bài này bạn sẽ:
  • Dùng signal và computed cho state của component
  • Biết khi nào dùng và không dùng effect
  • Tránh vòng lặp và đọc signal ngoài ý muốn

#Signals: reactivity bạn đã biết, dưới tên khác

Tin vui cho dân Vue: signals của Angular gần như là ref + computed + watchEffect. Cùng ý tưởng (theo dõi phụ thuộc tự động), cùng cách nghĩ. Khác chủ yếu ở cú pháp đọc / ghi.

#signal

counter.ts
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-counter',
  template: `
    <p>Đã chấm: {{ graded() }}</p>
    <button (click)="graded.update(n => n + 1)">+1</button>
    <button (click)="graded.set(0)">Đặt lại</button>
  `,
})
export class Counter {
  graded = signal(0);              // WritableSignal<number>
  name = signal<string | null>(null); // khai báo kiểu khi giá trị đầu chưa đủ để suy ra
}

Mỗi lần set / update với giá trị khác, mọi nơi đang đọc signal đó (template, computed, effect) được báo để cập nhật.

Signal chứa object và mảng: luôn thay mới

Đây là khác biệt lớn nhất với reactive / ref của Vue. Vue dùng Proxy nên list.value.push(x) vẫn kích hoạt cập nhật. Signal so sánh bằng Object.is: nếu bạn sửa trực tiếp object bên trong, tham chiếu không đổi, không ai được báo.

TypeScriptSai / nguy hiểm
students = signal<Student[]>([]);

add(s: Student) {
  this.students().push(s);          // ✘ sửa mảng tại chỗ: giao diện KHÔNG cập nhật
}
rename(id: number, name: string) {
  this.students().find((x) => x.id === id)!.name = name; // ✘ tương tự
}
TypeScriptĐúng / nên làm
add(s: Student) {
  this.students.update((list) => [...list, s]);                       // ✓ mảng mới
}
rename(id: number, name: string) {
  this.students.update((list) => list.map((x) => (x.id === id ? { ...x, name } : x))); // ✓ object mới
}
remove(id: number) {
  this.students.update((list) => list.filter((x) => x.id !== id));
}

Nếu bạn từng dùng Pinia với $patch hay Redux / React, cách "luôn tạo object mới" (immutable) này quen thuộc. Mẹo: khai báo signal<readonly Student[]> để TypeScript báo lỗi ngay khi bạn lỡ gọi .push.

#computed

TypeScript
students = signal<Student[]>([...]);
query = signal('');

filtered = computed(() => {
  const q = this.query().toLowerCase();
  return this.students().filter((s) => s.name.toLowerCase().includes(q));
});
count = computed(() => this.filtered().length);
average = computed(() => {
  const g = this.filtered().filter((s) => s.score != null);
  return g.length ? g.reduce((t, s) => t + s.score!, 0) / g.length : null;
});
  • Lười: chỉ tính khi có ai đọc.
  • Ghi nhớ: tính lại chỉ khi một signal nó đọc thay đổi.
  • Phụ thuộc động: chỉ theo dõi những signal thực sự được đọc trong lần chạy gần nhất. Ví dụ computed(() => this.showAll() ? this.all() : this.mine()): khi showAll() là false, thay đổi của all không làm nó tính lại.

Không gọi set / update bên trong computed. computed phải là hàm thuần (chỉ đọc và tính). Angular báo lỗi nếu bạn ghi signal trong computed.

#effect

effect chạy một hàm, ghi nhớ các signal nó đọc, và chạy lại khi chúng đổi. Dùng cho tác dụng phụ ra ngoài thế giới signal: ghi localStorage, ghi log, đồng bộ với thư viện không phải Angular (bản đồ, biểu đồ), cập nhật tiêu đề trang.

TypeScript
import { Component, effect, signal } from '@angular/core';

export class Settings {
  theme = signal<'light' | 'dark'>((localStorage.getItem('theme') as 'light' | 'dark') ?? 'light');

  constructor() {
    // effect phải được tạo trong "injection context": constructor, khởi tạo thuộc tính
    effect(() => {
      const t = this.theme();                     // đọc → được theo dõi
      localStorage.setItem('theme', t);
      document.documentElement.dataset['theme'] = t;
    });
  }
}

Effect chạy ít nhất một lần, chạy bất đồng bộ (trong lúc Angular cập nhật giao diện, không ngay khi bạn gọi set), và tự huỷ khi component bị huỷ.

Khi nào KHÔNG dùng effect

Đây là sai lầm phổ biến nhất (và cũng là lỗi kinh điển với watch trong Vue): dùng effect để tính state từ state.

TypeScriptSai / nguy hiểm
total = signal(0);
constructor() {
  effect(() => {
    this.total.set(this.items().reduce((t, x) => t + x.price, 0)); // ✘ dùng effect để đồng bộ hai signal
  });
}
TypeScriptĐúng / nên làm
total = computed(() => this.items().reduce((t, x) => t + x.price, 0)); // ✓

Effect ghi signal gây ra một vòng cập nhật thừa, dễ tạo vòng lặp, và giá trị bị lệch một nhịp. Quy tắc: giá trị suy ra từ giá trị khác → computed. Hành động ra bên ngoài → effect. Cần một state vừa suy ra vừa sửa được → linkedSignal (phần dưới).

Ở dự án hotoedu (ứng dụng Angular thật), một effect đọc và ghi cùng signal đã gây vòng lặp gọi API liên tục, đẩy số lượt đọc database lên hơn 100 triệu dòng mỗi ngày trước khi bị phát hiện. Mỗi effect có gọi API hoặc ghi signal phải được xem xét kỹ khi review code.

untracked: đọc mà không theo dõi

TypeScript
effect(() => {
  const id = this.classId();                    // theo dõi: đổi lớp → chạy lại
  const user = untracked(() => this.user());    // chỉ đọc, KHÔNG chạy lại khi user đổi
  this.analytics.track('open_class', { id, userId: user.id });
});

Bất kỳ hàm nào được gọi trong effect mà bên trong có đọc signal cũng sẽ bị theo dõi. Bọc lời gọi đó bằng untracked(() => ...) nếu bạn chỉ muốn effect phụ thuộc vào vài signal đầu.

Dọn dẹp trong effect

TypeScript
effect((onCleanup) => {
  const id = setInterval(() => this.tick.update((t) => t + 1), this.periodMs());
  onCleanup(() => clearInterval(id)); // chạy trước lần chạy kế tiếp và khi component bị huỷ
});

#linkedSignal: state suy ra nhưng vẫn sửa được

Bài toán: danh sách lớp đến từ input; component cho chọn một lớp; khi danh sách đổi thì lựa chọn phải về lớp đầu tiên (hoặc giữ lựa chọn nếu lớp đó còn). Với Vue bạn hay viết ref + watch. Angular có linkedSignal:

TypeScript
classes = input.required<Classroom[]>();

// Mặc định = lớp đầu tiên mỗi khi danh sách đổi, nhưng người dùng vẫn set() được
selected = linkedSignal(() => this.classes()[0] ?? null);

// Dạng đầy đủ: giữ lựa chọn cũ nếu còn trong danh sách mới
selectedKeep = linkedSignal<Classroom[], Classroom | null>({
  source: this.classes,
  computation: (list, previous) =>
    list.find((c) => c.id === previous?.value?.id) ?? list[0] ?? null,
});

pick(c: Classroom) {
  this.selected.set(c);
}

Một ví dụ thường gặp khác: count = linkedSignal(() => this.start()), component có giá trị ban đầu từ input nhưng tự thay đổi được sau đó (bài 0).

#Signal và zoneless

Ở Angular cũ, giao diện cập nhật nhờ Zone.js "đoán" khi nào có thể có thay đổi (sau mỗi click, mỗi request). Với signals, Angular biết chính xác component nào đọc signal nào, nên ứng dụng chạy được không cần Zone.js (zoneless), nhẹ hơn và nhanh hơn. Bài 16 đi sâu. Hệ quả thực tế: trong ứng dụng zoneless, thuộc tính thường của class không tự cập nhật giao diện nữa:

TypeScriptSai / nguy hiểm
// ứng dụng zoneless
count = 0;
ngOnInit() { setTimeout(() => this.count = 5, 1000); } // ✘ giao diện vẫn hiện 0
TypeScriptĐúng / nên làm
count = signal(0);
ngOnInit() { setTimeout(() => this.count.set(5), 1000); } // ✓ giao diện hiện 5

Quy tắc đơn giản cho code mới: mọi state hiển thị trên giao diện đều là signal (hoặc computed, input, model). Thuộc tính thường chỉ dùng cho hằng số và thứ không hiển thị.

#So sánh khi signal "bằng nhau"

TypeScript
filter = signal({ q: '', page: 1 }, { equal: (a, b) => a.q === b.q && a.page === b.page });
filter.set({ q: '', page: 1 }); // object mới nhưng "bằng" → không ai được báo

Mặc định là Object.is. Tuỳ chọn equal hữu ích khi signal chứa object được tạo lại thường xuyên.

Câu hỏi nhanh. items = signal<Item[]>([]). Gọi this.items().push(x). Giao diện có cập nhật không?

Signal không dùng Proxy. Chỉ set / update với giá trị mới mới kích hoạt cập nhật.

Câu hỏi nhanh. Cần fullName luôn bằng first + ' ' + last. Cách đúng?

Giá trị suy ra từ giá trị khác luôn là computed. Effect ghi signal là anti-pattern.

Câu hỏi nhanh. Trong effect, gọi this.logService.log(this.page()) và bên trong log() có đọc signal user. Effect sẽ chạy lại khi nào?

Bọc lời gọi bằng untracked nếu chỉ muốn phụ thuộc vào page.

#Bài tập

Giỏ chọn học sinh có lưu localStorage

Viết component quản lý danh sách học sinh được chọn để giao bài bổ sung: có ô tìm, danh sách 6 học sinh (lọc theo ô tìm), bấm vào tên để chọn / bỏ chọn, hiển thị "Đã chọn N em", nút "Bỏ chọn tất cả". Danh sách đã chọn được lưu vào localStorage và khôi phục khi tải lại trang.

Gợi ý từng bước

  1. State: query = signal(''), selected = signal<ReadonlySet<number>>(new Set(đọc từ localStorage)).
  2. Bật / tắt: tạo Set mới mỗi lần, const next = new Set(cũ); next.has(id) ? next.delete(id) : next.add(id); this.selected.set(next).
  3. visible = computed(...) lọc theo query, count = computed(() => this.selected().size).
  4. Lưu: effect(() => localStorage.setItem('chon', JSON.stringify([...this.selected()]))).
  5. Đọc localStorage có thể lỗi (chế độ ẩn danh, JSON hỏng): bọc trong try/catch.
Xem lời giải
student-picker.ts
import { Component, computed, effect, signal } from '@angular/core';

const KEY = 'chon-hoc-sinh';

function loadSelected(): Set<number> {
  try {
    const raw = JSON.parse(localStorage.getItem(KEY) ?? '[]');
    return new Set(Array.isArray(raw) ? raw.filter((x) => typeof x === 'number') : []);
  } catch {
    return new Set();
  }
}

@Component({
  selector: 'app-student-picker',
  template: `
    <input placeholder="Tìm học sinh" [value]="query()" (input)="query.set($any($event.target).value)" />
    <ul>
      @for (s of visible(); track s.id) {
        <li [class.on]="selected().has(s.id)" (click)="toggle(s.id)">{{ s.name }}</li>
      } @empty {
        <li>Không có học sinh khớp "{{ query() }}"</li>
      }
    </ul>
    <p>Đã chọn {{ count() }} em
      <button (click)="selected.set(empty)" [disabled]="count() === 0">Bỏ chọn tất cả</button>
    </p>
  `,
  styles: `li { cursor: pointer; padding: 4px 8px; } .on { background: #dcfce7; font-weight: 600; }`,
})
export class StudentPicker {
  protected readonly empty: ReadonlySet<number> = new Set();
  protected students = [
    { id: 1, name: 'Nguyễn An' }, { id: 2, name: 'Trần Bình' }, { id: 3, name: 'Lê Chi' },
    { id: 4, name: 'Phạm Dũng' }, { id: 5, name: 'Võ Hà' }, { id: 6, name: 'Đỗ Lan' },
  ];
  protected query = signal('');
  protected selected = signal<ReadonlySet<number>>(loadSelected());
  protected visible = computed(() => {
    const q = this.query().trim().toLowerCase();
    return this.students.filter((s) => s.name.toLowerCase().includes(q));
  });
  protected count = computed(() => this.selected().size);

  constructor() {
    effect(() => {
      try {
        localStorage.setItem(KEY, JSON.stringify([...this.selected()]));
      } catch {
        // chế độ ẩn danh / bị chặn: bỏ qua, tính năng vẫn chạy trong phiên
      }
    });
  }

  protected toggle(id: number) {
    const next = new Set(this.selected());
    next.has(id) ? next.delete(id) : next.add(id);
    this.selected.set(next);
  }
}
