Giao tiếp giữa component: input, output, model

input() / output() / model(), required, transform, alias, content projection với ng-content (slot của Angular), viewChild / contentChild.

Học xong bài này bạn sẽ:
  • Truyền dữ liệu cha → con và sự kiện con → cha
  • Làm component có two-way binding bằng model()
  • Dùng ng-content thay cho slot

#input()

grade-badge.ts
import { Component, booleanAttribute, computed, input, numberAttribute } from '@angular/core';

@Component({
  selector: 'app-grade-badge',
  template: `<span [class]="tone()">{{ label() }}{{ score() }}</span>`,
})
export class GradeBadge {
  score = input.required<number>();                     // bắt buộc: thiếu là lỗi biên dịch ở nơi dùng
  label = input('Điểm: ');                              // có mặc định, kiểu suy ra là string
  max = input(10, { transform: numberAttribute });      // max="10" (chuỗi) tự đổi thành số
  compact = input(false, { transform: booleanAttribute }); // <app-grade-badge compact /> → true
  studentName = input<string | undefined>(undefined, { alias: 'student' }); // dùng [student]="..."

  protected tone = computed(() => (this.score() / this.max() >= 0.8 ? 'good' : this.score() / this.max() >= 0.5 ? 'ok' : 'low'));
}
nơi dùng
<app-grade-badge [score]="9" />
<app-grade-badge [score]="s.score" label="" compact max="20" />
<app-grade-badge />            <!-- ✘ lỗi biên dịch: thiếu input bắt buộc 'score' -->
  • Input là signal chỉ đọc: đọc bằng score(), dùng được trong computed / effect. Con không được set input (giống không được sửa props trong Vue).
  • transform chuyển giá trị trước khi lưu. booleanAttribute cho phép viết thuộc tính trần như HTML (<app-x disabled />), giống boolean prop của Vue.

Khác Vue: Vue có withDefaults và kiểm tra kiểu prop lúc chạy. Angular kiểm tra hoàn toàn lúc biên dịch, nên truyền sai kiểu ở template là lỗi build. Không có kiểu "validator" lúc chạy cho input.

Muốn "sửa giá trị input ở trong con"? Đó là dấu hiệu cần model() (hai chiều) hoặc linkedSignal(() => this.input()) (bản sao cục bộ có thể sửa).

#output()

assignment-item.ts
import { Component, input, output } from '@angular/core';

@Component({
  selector: 'app-assignment-item',
  template: `
    <span>{{ assignment().title }}</span>
    <button (click)="edit.emit(assignment().id)">Sửa</button>
    <button (click)="remove.emit(assignment())">Xoá</button>
  `,
})
export class AssignmentItem {
  assignment = input.required<Assignment>();
  edit = output<number>();          // phát id
  remove = output<Assignment>();    // phát cả object
  closed = output();                // không mang dữ liệu: closed.emit()
}
cha
@for (a of assignments(); track a.id) {
  <app-assignment-item [assignment]="a" (edit)="openEditor($event)" (remove)="confirmRemove($event)" />
}

$event trong template của cha chính là giá trị được emit. Khác DOM event, output của Angular không nổi bọt (bubble): chỉ cha trực tiếp nghe được, giống emit của Vue.

#model(): two-way binding cho component

rating.ts
import { Component, input, model } from '@angular/core';

@Component({
  selector: 'app-rating',
  template: `
    @for (n of stars; track n) {
      <button type="button" [class.on]="n <= value()" (click)="value.set(n)" [attr.aria-label]="n + ' sao'">★</button>
    }
  `,
  styles: `button { border: 0; background: none; font-size: 22px; color: #cbd5e1; } .on { color: #f59e0b; }`,
})
export class Rating {
  value = model(0);                 // signal ghi được; set() tự phát sự kiện valueChange
  protected stars = [1, 2, 3, 4, 5];
}

ng-template: scoped slot

data-list.ts
import { Component, contentChild, input, TemplateRef } from '@angular/core';
import { JsonPipe, NgTemplateOutlet } from '@angular/common';

@Component({
  selector: 'app-data-list',
  imports: [NgTemplateOutlet, JsonPipe],
  template: `
    <ul>
      @for (item of items(); track $index) {
        <li>
          <ng-container *ngTemplateOutlet="row() ?? defaultRow; context: { $implicit: item, index: $index }" />
        </li>
      }
    </ul>
    <ng-template #defaultRow let-item>{{ item | json }}</ng-template>
  `,
})
export class DataList<T> {
  items = input.required<T[]>();
  row = contentChild<TemplateRef<{ $implicit: T; index: number }>>('row'); // template cha truyền vào
}
cha
<app-data-list [items]="students()">
  <ng-template #row let-s let-i="index">
    {{ i + 1 }}. <b>{{ s.name }}</b> — {{ s.score ?? 'chưa chấm' }}
  </ng-template>
</app-data-list>

let-s nhận $implicit, let-i="index" nhận trường index của context. Giống <template #row="{ item, index }"> của Vue, chỉ dài hơn.

#viewChild và contentChild

TypeScript
import { Component, ElementRef, afterNextRender, viewChild } from '@angular/core';

@Component({
  selector: 'app-quick-add',
  imports: [DatePicker],
  template: `
    <input #title placeholder="Tên bài" />
    <app-date-picker />
    <button (click)="picker().open()">Chọn hạn</button>
  `,
})
export class QuickAdd {
  title = viewChild.required<ElementRef<HTMLInputElement>>('title'); // theo #tên
  picker = viewChild.required(DatePicker);                            // theo kiểu component

  constructor() {
    afterNextRender(() => this.title().nativeElement.focus()); // DOM đã có sau lần render đầu
  }
}
HàmTìm trongVue
viewChild / viewChildrentemplate của chính componentuseTemplateRef / ref
contentChild / contentChildrennội dung cha chiếu vào qua ng-contentkhông có tương đương trực tiếp (slots API)

Kết quả là signal: viewChild() trả undefined cho tới khi phần tử xuất hiện, bản .required báo lỗi nếu đọc quá sớm. Đọc trong event handler, afterNextRender hoặc effect, không đọc trong constructor.

Hạn chế gọi method của con qua viewChild. Phần lớn trường hợp, truyền input / nhận output là đủ và dễ theo dõi hơn. viewChild hợp với: focus, scroll, gọi open() của dialog, tích hợp thư viện DOM.

#Đọc code cũ: @Input, @Output

TypeScript
export class OldItem implements OnChanges {
  @Input() title = '';
  @Input({ required: true }) id!: number;
  @Input() set score(v: number) { this._score = v; this.recalc(); } // setter để phản ứng khi đổi
  @Output() removed = new EventEmitter<number>();
  @ViewChild('box') box?: ElementRef;

  ngOnChanges(changes: SimpleChanges) {
    if (changes['title']) { /* title vừa đổi */ }
  }
}

Chuyển đổi tự động: ng g @angular/core:signal-input-migration, ng g @angular/core:output-migration, ng g @angular/core:signal-queries-migration. Với input dạng signal, bạn không cần ngOnChanges hay setter nữa: dùng computed hoặc effect.

. Khai báo gì trong con?"> - open = input(false) và tự set nó + open = model(false) - open = output<boolean>() ? model() tạo cặp input open + output openChange, và cho con set() giá trị.

Câu hỏi nhanh. Cần một danh sách tái sử dụng mà cha quyết định mỗi dòng hiển thị thế nào, có truyền dữ liệu từng dòng ra. Dùng gì?

ng-content không truyền được dữ liệu ngược ra và không lặp được. Template mới làm được.

#Bài tập

Hộp thoại xác nhận dùng lại được

Viết component ConfirmDialog: mở / đóng bằng [(open)], tiêu đề qua input, nội dung chiếu qua ng-content, hai nút "Huỷ" (đóng) và nút xác nhận có chữ tuỳ chỉnh (mặc định "Đồng ý"), phát output confirmed. Bấm phím Escape thì đóng. Dùng nó để xác nhận xoá một bài tập.

Gợi ý từng bước

  1. open = model(false), title = input.required<string>(), okText = input('Đồng ý'), confirmed = output().
  2. Template bọc trong @if (open()) { ... }, nền mờ là một div phủ toàn màn hình.
  3. Escape: host: { '(document:keydown.escape)': 'open.set(false)' }.
  4. Nút xác nhận: confirmed.emit(); open.set(false).
Xem lời giải
confirm-dialog.ts
import { Component, input, model, output } from '@angular/core';

@Component({
  selector: 'app-confirm-dialog',
  host: { '(document:keydown.escape)': 'open.set(false)' },
  template: `
    @if (open()) {
      <div class="backdrop" (click)="open.set(false)"></div>
      <div class="box" role="dialog" aria-modal="true" [attr.aria-label]="title()">
        <h3>{{ title() }}</h3>
        <ng-content />
        <div class="actions">
          <button type="button" (click)="open.set(false)">Huỷ</button>
          <button type="button" class="danger" (click)="confirmed.emit(); open.set(false)">{{ okText() }}</button>
        </div>
      </div>
    }
  `,
  styles: `
    .backdrop { position: fixed; inset: 0; background: rgb(15 23 42 / .45); }
    .box { position: fixed; left: 50%; top: 30%; translate: -50% 0; background: #fff; border-radius: 14px; padding: 18px 20px; width: min(420px, 92vw); }
    .actions { display: flex; justify-content: flex-end; gap: 8px; margin-top: 14px; }
    .danger { background: #dc2626; color: #fff; border: 0; border-radius: 8px; padding: 6px 14px; }
  `,
})
export class ConfirmDialog {
  open = model(false);
  title = input.required<string>();
  okText = input('Đồng ý');
  confirmed = output();
}
assignment-page.ts (dùng thử)
@Component({

Xoá bài tập?

Bài "Bài 3: Phân số" và mọi bài nộp sẽ bị xoá. Không thể hoàn tác.

Giải thích: cha giữ state asking, con đọc và đóng nó qua model. Nội dung câu hỏi do cha quyết định qua ng-content, nên dialog dùng lại được cho mọi loại xác nhận. host nghe phím trên document, Angular tự gỡ listener khi component bị huỷ. Bản production nên dùng Dialog của Angular CDK (bài 19): nó xử lý giữ focus trong hộp thoại và trả focus khi đóng.
