Vì sao cần ôn lại TypeScript

Ở Vue, TypeScript là tuỳ chọn, và kể cả khi dùng thì <script setup> giấu gần hết class và decorator. Angular thì ngược lại: mọi thứ là class có decorator, dự án mặc định bật strict, template cũng được kiểm tra kiểu. Bài này ôn đúng những phần TypeScript mà Angular dùng mỗi ngày.

Class: viên gạch của Angular

export class ClassCard {
  // thuộc tính có giá trị ban đầu: kiểu được suy ra (number)
  count = 0;

  // khai báo kiểu rõ ràng
  title: string = 'Lớp 5A';

  // readonly: không gán lại được sau khi khởi tạo
  readonly maxStudents = 40;

  // private / protected / public (mặc định public)
  private secret = 'chỉ trong class';
  protected shown = 'class con và template dùng được';

  // ! : "tôi hứa sẽ gán trước khi dùng" (definite assignment) — hạn chế dùng
  teacherName!: string;

  // method
  rename(next: string): void {
    this.title = next;
  }

  // getter: dùng như thuộc tính
  get isFull(): boolean {
    return this.count >= this.maxStudents;
  }
}

Trong <script setup> của Vue, mọi biến khai báo ở top-level đều dùng được trong template. Ở Angular, template chỉ thấy các thành viên public hoặc protected của class. Quy ước hiện đại: những thứ chỉ dùng trong template thì để protected, để code bên ngoài không gọi nhầm.

Luôn dùng this. khi truy cập thuộc tính trong method. Quên this là lỗi kinh điển của người đến từ Vue Composition API (nơi biến chỉ là biến).

Decorator

Decorator là hàm gắn vào class (hoặc thuộc tính, tham số) bằng cú pháp @Ten(...), cho Angular biết class này là gì và cấu hình ra sao.

DecoratorGắn vàoNghĩa
@Component({...})classclass này là một component: selector, template, style, imports
@Directive({...})classdirective (bài {{n:directive-pipe}})
@Pipe({...})classpipe biến đổi giá trị trong template
@Injectable({...})classservice có thể được inject (bài {{n:di-service}})
@Input(), @Output(), @HostListener(), @ViewChild()thuộc tính / methodkiểu cũ, nay thay bằng hàm input(), output(), host: {}, viewChild()

Ở Angular hiện đại bạn chỉ còn dùng decorator ở cấp class. Các decorator thuộc tính chuyển thành hàm (signal-based), nên code ngắn và an toàn kiểu hơn.

// Kiểu cũ (vẫn gặp nhiều trong dự án công ty)
@Component({ selector: 'app-old', template: '...' })
export class OldCard implements OnChanges {
  @Input() title = '';
  @Input({ required: true }) id!: number;
  @Output() removed = new EventEmitter();
  @ViewChild('box') box!: ElementRef;
}

// Kiểu mới
@Component({ selector: 'app-new', template: '...' })
export class NewCard {
  title = input('');
  id = input.required();
  removed = output();
  box = viewChild.required>('box');
}

Interface, type và mô hình dữ liệu

// Dữ liệu từ API: dùng interface hoặc type, KHÔNG dùng class
export interface Assignment {
  id: number;
  classId: number;
  title: string;
  dueDate: string;              // 'YYYY-MM-DD' — JSON không có kiểu Date
  status: AssignmentStatus;
  note?: string;                // có thể không có
  attachments: readonly Attachment[];
}

export type AssignmentStatus = 'draft' | 'published' | 'closed'; // union của chuỗi thay cho enum

export interface Attachment {
  key: string;
  name: string;
  size: number;
}

// Dữ liệu gửi lên khi tạo mới: suy ra từ kiểu chính
export type NewAssignment = Omit;
export type AssignmentPatch = Partial>;

Ưu tiên union chuỗi ('draft' | 'published') hơn enum: không sinh thêm code JavaScript, dễ so khớp với JSON từ API, và template so sánh được trực tiếp @if (a.status === 'draft').

Generic

Bạn sẽ gặp generic ở mọi nơi trong Angular: signal<number>(), input.required<string>(), http.get<Assignment[]>(url), Observable<T>, FormControl<string>.

// Kiểu chung cho mọi API phân trang
export interface Page {
  items: T[];
  page: number;
  totalPages: number;
}

// Hàm generic: dùng cho mọi loại phần tử
export function byId(list: readonly T[], id: number): T | undefined {
  return list.find((x) => x.id === id);
}

const page: Page = await firstValueFrom(http.get>('/api/assignments'));
const a = byId(page.items, 9); // a có kiểu Assignment | undefined

http.get<Assignment[]>(url) chỉ là lời hứa với trình biên dịch, không kiểm tra dữ liệu thật lúc chạy. Server trả sai cấu trúc thì code vẫn chạy và lỗi ở chỗ khác. Với dữ liệu quan trọng, kiểm tra bằng thư viện như Zod / Valibot.

Narrowing và kiểu cho sự kiện DOM

onInput(e: Event) {
  const value = (e.target as HTMLInputElement).value; // ép kiểu target
}

onKey(e: KeyboardEvent) {
  if (e.key === 'Enter') this.save();
}

// Phân biệt các loại kết quả bằng trường chung (discriminated union)
type LoadState =
  | { kind: 'loading' }
  | { kind: 'error'; message: string }
  | { kind: 'ok'; data: T };

function render(s: LoadState) {
  switch (s.kind) {
    case 'loading': return 'Đang tải…';
    case 'error': return s.message;        // ở đây TS biết s có message
    case 'ok': return `${s.data.length} bài`;
  }
}

Trong template, Angular cũng có cú pháp gọn để lấy giá trị từ sự kiện: (input)="name.set($any($event.target).value)". $any tắt kiểm tra kiểu cho một biểu thức, dùng hạn chế. Cách đúng hơn là truyền $event vào method có kiểu, hoặc dùng forms (bài {{n:forms}}).

Bài tập

Mô hình dữ liệu cho "Sổ bài tập"

Viết file models.ts mô tả: Classroom (id, tên, sĩ số, năm học), Submission (id, mã học sinh, mã bài, trạng thái: chưa nộp / đã nộp / đã chấm, điểm có thể không có, nhận xét có thể không có), bảng nhãn tiếng Việt cho trạng thái, và hàm generic groupBy nhóm danh sách theo một khoá.

Gợi ý từng bước

  1. Trạng thái: type SubmissionStatus = 'missing' | 'submitted' | 'graded'.
  2. Điểm có thể không có: score: number | null (API thường trả null) hoặc score?: number.
  3. Bảng nhãn: Record<SubmissionStatus, string>.
  4. groupBy<T, K extends string | number>(list: readonly T[], key: (x: T) => K): Record<K, T[]>.
Xem lời giải 
export interface Classroom {
  id: number;
  name: string;
  capacity: number;
  schoolYear: `${number}-${number}`; // template literal type: '2026-2027'
}

export type SubmissionStatus = 'missing' | 'submitted' | 'graded';

export interface Submission {
  id: number;
  studentId: number;
  assignmentId: number;
  status: SubmissionStatus;
  score: number | null;
  comment?: string;
}

export const SUBMISSION_LABEL: Record = {
  missing: 'Chưa nộp',
  submitted: 'Đã nộp',
  graded: 'Đã chấm',
};

export function groupBy(list: readonly T[], key: (x: T) => K): Record {
  const out = {} as Record;
  for (const item of list) {
    (out[key(item)] ??= []).push(item);
  }
  return out;
}

// Dùng thử
const subs: Submission[] = [
  { id: 1, studentId: 7, assignmentId: 9, status: 'graded', score: 9 },
  { id: 2, studentId: 8, assignmentId: 9, status: 'missing', score: null },
  { id: 3, studentId: 9, assignmentId: 9, status: 'graded', score: 7 },
];
const byStatus = groupBy(subs, (s) => s.status);
console.log(Object.keys(byStatus), byStatus.graded.length);

Giải thích: schoolYear dùng template literal type nên gán 'năm nay' sẽ lỗi biên dịch. ??= gán khi giá trị đang là null hoặc undefined, gọn cho việc tạo mảng lần đầu. Kiểu trả về Record<K, T[]> giúp byStatus.graded có gợi ý và kiểm tra kiểu.
