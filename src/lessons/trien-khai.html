Build production

ng build                         # mặc định configuration production
ng build --configuration staging # cấu hình riêng (khai báo trong angular.json)

Builder @angular/build:application (esbuild) làm: biên dịch AOT, tree-shaking, minify, tách chunk theo route / defer, đặt hash vào tên file, sinh index.html gắn đúng file. Kết quả nằm ở dist/<tên-dự-án>/browser/: toàn file tĩnh, phục vụ được từ bất kỳ máy chủ web hay CDN nào.

Cấu hình theo môi trường

Cách 1: environment lúc build

ng g environments

export const environment = {
  production: true,
  apiUrl: 'https://api.sobaitap.vn',
  sentryDsn: 'https://abc@o1.ingest.sentry.io/1',
};

export const environment = {
  production: false,
  apiUrl: '/api',
  sentryDsn: '',
};

angular.json có fileReplacements: khi build configuration development thì file environment.ts được thay bằng environment.development.ts. Giống .env.production của Vite, nhưng là file TypeScript có kiểu.

Mọi giá trị trong environment nằm trong bundle công khai. Chỉ đặt cấu hình công khai (URL API, khoá công khai), không bao giờ đặt bí mật.

Cách 2: cấu hình lúc chạy (một bản build, nhiều môi trường)

Muốn cùng một bản build deploy lên staging và production (đúng chuẩn "build một lần, chạy nhiều nơi"): tải file cấu hình khi khởi động.

fetch('/config.json')
  .then((r) => r.json())
  .then((cfg: AppConfig) =>
    bootstrapApplication(App, {
      ...appConfig,
      providers: [...appConfig.providers, { provide: APP_CONFIG, useValue: cfg }],
    }),
  );

Mỗi môi trường có config.json riêng (đặt bởi pipeline hoặc server), không cần build lại. Cũng có thể dùng provideAppInitializer(() => ...) để tải cấu hình trước khi ứng dụng chạy.

Deploy lên static hosting

Ứng dụng CSR là file tĩnh, chỉ cần một điều quan trọng: mọi đường dẫn không phải file đều trả về index.html (SPA fallback), để tải lại trang /lop/5 không bị 404.

Nơi deployCấu hình fallback
Netlifypublic/_redirects: /* /index.html 200
Cloudflare Pages / Workers static assetsmặc định SPA, hoặc not_found_handling: "single-page-application"
Firebase Hosting"rewrites": [{ "source": "**", "destination": "/index.html" }]
Nginxtry_files $uri $uri/ /index.html;
S3 + CloudFronttrang lỗi 403/404 → /index.html mã 200
server {
  listen 80;
  root /usr/share/nginx/html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  # file có hash: cache 1 năm
  location ~* \.(js|css|woff2|webp|png|svg)$ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }

  # index.html: không cache, để luôn lấy bản mới
  location = /index.html {
    add_header Cache-Control "no-cache";
  }
}

Nguyên tắc cache: file có hash trong tên cache vĩnh viễn, index.html không cache. Khi deploy, index.html mới trỏ tới file JS mới, người dùng tự lấy bản mới ở lần tải trang tiếp theo.

Sau deploy, người dùng đang mở trang cũ bấm sang route lazy sẽ tải chunk của bản cũ, nếu server đã xoá thì lỗi "Failed to fetch dynamically imported module". Giữ lại file của bản trước một thời gian, hoặc bắt lỗi này trong ErrorHandler và tự tải lại trang một lần.

Theo dõi lỗi trên production

@Injectable()
export class AppErrorHandler implements ErrorHandler {
  private reloaded = false;
  handleError(error: unknown) {
    const msg = String((error as Error)?.message ?? error);
    if (/Failed to fetch dynamically imported module|Loading chunk/.test(msg) && !this.reloaded) {
      this.reloaded = true;
      location.reload();                 // bản mới đã deploy: tải lại một lần
      return;
    }
    console.error(error);
    // gửi lên Sentry / công cụ theo dõi lỗi (lọc dữ liệu nhạy cảm)
  }
}

// app.config.ts
providers: [{ provide: ErrorHandler, useClass: AppErrorHandler }]

Bài tập

Pipeline deploy lên Cloudflare Pages

Viết workflow GitHub Actions: khi push lên main thì lint, test, build, rồi deploy thư mục build lên Cloudflare Pages. Đảm bảo SPA fallback, header bảo mật và cache đúng.

Gợi ý từng bước

  1. Deploy bằng npx wrangler pages deploy dist/so-bai-tap/browser --project-name so-bai-tap, cần secret CLOUDFLARE_API_TOKEN và CLOUDFLARE_ACCOUNT_ID.
  2. Cloudflare Pages tự fallback SPA khi không có file 404.html.
  3. Header: file public/_headers (được copy nguyên vào thư mục build).
  4. Cache: thêm quy tắc cho /*.js, /*.css trong _headers.
