Angular biết khi nào phải cập nhật giao diện bằng cách nào

Vue dùng Proxy: mỗi lần bạn gán count.value = 5, Vue biết ngay component nào đọc count và chỉ render lại component đó. Angular trong lịch sử làm khác hẳn, và hiện đang chuyển dần về mô hình giống Vue nhờ signals. Hiểu cả hai mô hình giúp bạn đọc được code cũ và sửa những lỗi "giao diện không cập nhật".

Ưu điểm: bạn sửa thuộc tính thường (this.count = 5) ở bất cứ đâu, giao diện tự cập nhật, không cần ref hay signal. Nhược điểm:

  • Kiểm tra mọi component sau mọi sự kiện, kể cả khi chẳng có gì đổi (cuộn chuột, mousemove, setInterval của thư viện quảng cáo).
  • Zone.js nặng khoảng 30 KB và vá các API của trình duyệt, gây khó gỡ lỗi (stack trace dài) và không theo kịp các API mới (async / await gốc phải hạ cấp).
  • Cập nhật từ ngoài "vùng" của Angular (thư viện tự tạo WebSocket) có thể không được phát hiện.

OnPush: chỉ kiểm tra khi cần

@Component({
  selector: 'app-student-row',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `...`,
})
export class StudentRow { ... }

Component OnPush chỉ được kiểm tra lại khi:

  • một input nhận tham chiếu mới (so sánh ===),
  • một sự kiện xảy ra trong template của nó hoặc con của nó,
  • một signal mà template của nó đọc thay đổi,
  • async pipe trong template nhận giá trị mới,
  • bạn gọi ChangeDetectorRef.markForCheck().

Lỗi kinh điển với OnPush: cha sửa object tại chỗ (this.student.name = 'An') rồi truyền vào con OnPush. Tham chiếu không đổi nên con không cập nhật. Cách sửa luôn là: tạo object mới. Đây cũng chính là quy tắc của signals, nên viết theo kiểu bất biến là đúng với mọi chế độ.

Với code mới dùng signals cho mọi state, nên đặt OnPush cho mọi component (có thể cấu hình CLI sinh sẵn: "@schematics/angular:component": { "changeDetection": "OnPush" } trong angular.json). Từ Angular 20+ có bàn luận đưa OnPush thành mặc định, xem ghi chú phát hành của phiên bản bạn dùng.

Hệ quả quan trọng: thuộc tính thường của class không còn tự cập nhật giao diện khi bị đổi trong setTimeout, subscribe, .then(), listener tự gắn.

// ứng dụng zoneless
loading = true;
data: Item[] = [];
ngOnInit() {
  this.api.list().subscribe((d) => {
    this.data = d;           // ✘ giao diện không biết để cập nhật
    this.loading = false;
  });
}

loading = signal(true);
data = signal([]);
ngOnInit() {
  this.api.list().subscribe((d) => {
    this.data.set(d);        // ✓
    this.loading.set(false);
  });
}
// hoặc gọn hơn: data = toSignal(this.api.list(), { initialValue: [] })

Chuyển ứng dụng cũ sang zoneless:

providers: [
  provideZonelessChangeDetection(),
  // và bỏ "zone.js" khỏi polyfills trong angular.json
]

Rồi tìm các chỗ sửa state ngoài sự kiện template (subscribe, setTimeout, thư viện bên ngoài) và đổi sang signal hoặc gọi markForCheck().

Zoneless + signals đưa Angular về rất gần mô hình reactivity của Vue: thay đổi state được theo dõi chi tiết, giao diện cập nhật đúng chỗ. Khác biệt còn lại: Angular gộp cập nhật theo component (kiểm tra cả template của component bị đánh dấu), còn Vue gộp theo component và so sánh virtual DOM.

Lỗi ExpressionChangedAfterItHasBeenChecked

Ở chế độ phát triển, sau mỗi lượt kiểm tra Angular chạy thêm một lượt để chắc rằng không có giá trị nào đổi trong lúc đang kiểm tra. Nếu có, bạn gặp lỗi nổi tiếng:

ERROR RuntimeError: NG0100: ExpressionChangedAfterItHasBeenCheckedError: Expression has changed after it was checked.
Previous value: 'false'. Current value: 'true'. Expression location: _ClassLayout component.

Nguyên nhân thường gặp: component con, trong vòng đời của nó (ngAfterViewInit, getter có tác dụng phụ), thay đổi state mà cha đã hiển thị. Ví dụ con báo "đang tải" lên service ngay trong ngOnInit trong khi cha đã render cờ loading.

Bài tập

Chuyển một component kiểu cũ sang zoneless

Component dưới đây chạy đúng với Zone.js nhưng "đứng hình" khi bật zoneless. Tìm mọi chỗ cần sửa và viết lại.

@Component({
  selector: 'app-live-board',
  template: `
    
Đã nộp: {{ submitted }} / {{ total }}

    
Cập nhật lúc {{ updatedAt | date: 'HH:mm:ss' }}

    @if (offline) { 
Mất kết nối
 }
  `,
})
export class LiveBoard implements OnInit, OnDestroy {
  submitted = 0;
  total = 0;
  updatedAt = new Date();
  offline = false;
  private ws?: WebSocket;
  private sub?: Subscription;

  constructor(private api: BoardApi) {}

  ngOnInit() {
    this.sub = this.api.summary().subscribe((s) => { this.submitted = s.submitted; this.total = s.total; });
    this.ws = new WebSocket('wss://example.com/live');
    this.ws.onmessage = (e) => { this.submitted = JSON.parse(e.data).submitted; this.updatedAt = new Date(); };
    window.addEventListener('offline', () => (this.offline = true));
    window.addEventListener('online', () => (this.offline = false));
  }

  ngOnDestroy() {
    this.sub?.unsubscribe();
    this.ws?.close();
  }
}

Gợi ý từng bước

  1. Mọi thứ hiển thị trên template đổi thành signal.
  2. subscribe gán vào thuộc tính → dùng toSignal hoặc set trong subscribe.
  3. WebSocket onmessage và listener window chạy ngoài sự kiện template → phải set signal.
  4. Listener window không bao giờ được gỡ → dùng host: { '(window:offline)': ... } để Angular tự gỡ.
Xem lời giải 
@Component({
  selector: 'app-live-board',
  imports: [DatePipe],
  changeDetection: ChangeDetectionStrategy.OnPush,
  host: {
    '(window:offline)': 'offline.set(true)',
    '(window:online)': 'offline.set(false)',
  },
  template: `
    
Đã nộp: {{ submitted() }} / {{ total() }}

    
Cập nhật lúc {{ updatedAt() | date: 'HH:mm:ss' }}

    @if (offline()) { 
Mất kết nối
 }
  `,
})
export class LiveBoard {
  private api = inject(BoardApi);
  protected submitted = signal(0);
  protected total = signal(0);
  protected updatedAt = signal(new Date());
  protected offline = signal(!navigator.onLine);

  constructor() {
    this.api.summary().pipe(takeUntilDestroyed()).subscribe((s) => {
      this.submitted.set(s.submitted);
      this.total.set(s.total);
    });

    const ws = new WebSocket('wss://example.com/live');
    ws.onmessage = (e) => {
      this.submitted.set(JSON.parse(e.data).submitted);
      this.updatedAt.set(new Date());
    };
    inject(DestroyRef).onDestroy(() => ws.close());
  }
}

Giải thích: sau khi sửa, mọi cập nhật đi qua signal nên Angular biết đúng lúc cần render, kể cả khi dữ liệu đến từ WebSocket hay sự kiện window. Listener khai báo trong host được tự gỡ, không còn rò rỉ (bản cũ gắn listener mới mỗi lần component được tạo và không bao giờ gỡ). OnPush giờ an toàn vì không còn state nào nằm ngoài signal. Lưu ý navigator không có khi SSR: ứng dụng có SSR thì đọc trong afterNextRender (bài {{n:ssr}}).
