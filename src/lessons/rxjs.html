Vì sao Angular dùng RxJS

Promise cho bạn một giá trị trong tương lai. Observable cho bạn một dòng giá trị theo thời gian: các lần gõ phím, các lần URL đổi, các message WebSocket, tiến trình upload. HttpClient, router, forms của Angular đều phát Observable. Với signals, bạn cần RxJS ít hơn nhiều so với Angular vài năm trước, nhưng vẫn phải đọc được và dùng đúng vài operator.

Vue không bắt bạn dùng RxJS. Gần nhất là watch + debounce của VueUse. Hãy nghĩ Observable như "mảng theo thời gian": map, filter giống mảng, cộng thêm các operator về thời gian (debounceTime) và về "khi có giá trị mới thì làm gì với việc cũ" (switchMap).

Tìm kiếm có debounce: ví dụ kinh điển

import { Component, inject, signal } from '@angular/core';
import { toObservable, toSignal } from '@angular/core/rxjs-interop';
import { catchError, debounceTime, distinctUntilChanged, filter, map, of, switchMap } from 'rxjs';

@Component({
  selector: 'app-student-search',
  template: `
    
    
    
      @for (s of results(); track s.id) { 
  • {{ s.name }} — {{ s.className }}
    •  }
    

  `,
})
export class StudentSearch {
  private api = inject(StudentApi);
  protected query = signal('');

  protected results = toSignal(
    toObservable(this.query).pipe(
      map((q) => q.trim()),
      debounceTime(300),
      distinctUntilChanged(),
      switchMap((q) => (q.length < 2 ? of([]) : this.api.search(q).pipe(catchError(() => of([]))))),
    ),
    { initialValue: [] },
  );
}

Vì sao switchMap: người dùng gõ "lan" rồi "lanh". Nếu request "lan" về sau request "lanh" (mạng chập chờn), không có switchMap thì kết quả cũ đè kết quả mới. switchMap huỷ request "lan" ngay khi "lanh" tới.

catchError đặt bên trong switchMap. Đặt ở ngoài thì lỗi đầu tiên làm cả dòng kết thúc vĩnh viễn: ô tìm kiếm "chết" sau một lần mạng lỗi.

Subscribe và huỷ: không để rò rỉ

Observable từ HttpClient tự kết thúc sau một response. Nhưng Observable "dài hạn" (valueChanges của form, interval, WebSocket, router events) chạy mãi: subscribe mà không huỷ thì component bị gỡ rồi vẫn chạy.

import { takeUntilDestroyed } from '@angular/core/rxjs-interop';

export class GradingForm {
  form = inject(FormBuilder).group({ score: [0] });

  constructor() {
    this.form.controls.score.valueChanges
      .pipe(debounceTime(500), takeUntilDestroyed())   // tự huỷ khi component bị huỷ
      .subscribe((s) => this.autosave(s));
  }
}

Thứ tự ưu tiên để không bao giờ phải tự unsubscribe:

  1. Không subscribe: dùng toSignal(obs$) hoặc | async trong template, Angular tự huỷ.
  2. takeUntilDestroyed() trong constructor (ngoài constructor thì truyền DestroyRef: takeUntilDestroyed(this.destroyRef)).
  3. Cách cũ bạn sẽ thấy: Subscription lưu lại rồi unsubscribe() trong ngOnDestroy, hoặc Subject destroy$ + takeUntil(this.destroy$).

Bài tập

Tự lưu ghi chú chấm bài

Ô nhận xét của giáo viên tự lưu sau khi ngừng gõ 800ms. Hiển thị trạng thái "Đang lưu…", "Đã lưu lúc HH:mm:ss", "Lưu lỗi, sẽ thử lại". Các lần lưu phải đúng thứ tự (không để bản cũ ghi đè bản mới), lỗi thì thử lại tối đa 2 lần. Dùng một hàm lưu giả trả Observable có độ trễ ngẫu nhiên.

Gợi ý từng bước

  1. Hàm giả: save = (t: string) => of(t).pipe(delay(200 + Math.random() * 800)), thỉnh thoảng throwError.
  2. Dòng: toObservable(this.note).pipe(skip(1), debounceTime(800), distinctUntilChanged(), ...).
  3. Lưu đúng thứ tự: concatMap. Hoặc switchMap nếu chỉ cần bản mới nhất (cũng tránh ghi đè).
  4. Bên trong: tap đặt trạng thái "Đang lưu", retry(2), catchError trả trạng thái lỗi.
  5. takeUntilDestroyed() và cập nhật signal status.
Xem lời giải 
import { Component, signal } from '@angular/core';
import { takeUntilDestroyed, toObservable } from '@angular/core/rxjs-interop';
import { catchError, concatMap, debounceTime, delay, distinctUntilChanged, map, of, retry, skip, startWith, throwError } from 'rxjs';

function fakeSave(text: string) {
  const ms = 200 + Math.random() * 800;
  return Math.random() < 0.2 ? throwError(() => new Error('mạng lỗi')).pipe(delay(ms)) : of(text).pipe(delay(ms));
}

@Component({
  selector: 'app-autosave-note',
  template: `
    
    {{ status() }}
  `,
  styles: `textarea { width: 100%; } .err { color: #dc2626; }`,
})
export class AutosaveNote {
  protected note = signal('');
  protected status = signal('Chưa có thay đổi');

  constructor() {
    toObservable(this.note)
      .pipe(
        skip(1),                         // bỏ giá trị đầu (rỗng lúc mở)
        debounceTime(800),
        distinctUntilChanged(),
        concatMap((text) =>
          fakeSave(text).pipe(
            retry(2),
            map(() => `Đã lưu lúc ${new Date().toLocaleTimeString('vi-VN')}`),
            catchError(() => of('Lưu lỗi, sẽ thử lại khi bạn gõ tiếp')),
            startWith('Đang lưu…'),
          ),
        ),
        takeUntilDestroyed(),
      )
      .subscribe((s) => this.status.set(s));
  }
}

Giải thích: startWith('Đang lưu…') phát ngay trạng thái đang lưu trước khi request xong. concatMap bảo đảm nếu lần lưu trước chưa xong mà có nội dung mới, nội dung mới sẽ được lưu sau, không chen ngang. retry(2) thử lại tối đa 2 lần rồi mới tới catchError. Đặt catchError bên trong concatMap nên một lần lỗi không làm chết dòng, lần gõ sau vẫn tự lưu.
