Vòng đời component và DOM

Constructor và ngOnInit, ngOnChanges, afterNextRender, afterRenderEffect, DestroyRef, ElementRef và Renderer2. So với onMounted, onUnmounted.

Học xong bài này bạn sẽ:
  • Đặt code vào đúng giai đoạn vòng đời
  • Dọn dẹp tài nguyên bằng DestroyRef
  • Thao tác DOM an toàn (cả khi SSR)

#Vòng đời của component

#constructor hay ngOnInit

TypeScript
export class ClassDetail implements OnInit {
  id = input.required<number>();
  private store = inject(ClassStore);   // ✓ inject ở khởi tạo thuộc tính / constructor

  constructor() {
    console.log(this.id());              // ✘ lỗi: input bắt buộc chưa có giá trị ở constructor
  }

  ngOnInit() {
    console.log(this.id());              // ✓ input đã được gán
  }
}
  • constructor: chỉ để inject và tạo signal / computed / effect. Input chưa có giá trị.
  • ngOnInit: chạy một lần khi input đã có giá trị lần đầu. Ở code cũ, đây là chỗ gọi API ban đầu.
  • Ở code hiện đại với signal, bạn ít cần ngOnInit: tải dữ liệu bằng resource / httpResource phụ thuộc input (bài 13) tự chạy khi input có giá trị và chạy lại khi input đổi.

Bẫy kinh điển: dùng ngOnInit để tải dữ liệu theo id từ route. Router dùng lại cùng component khi chỉ đổi tham số (/lop/1 → /lop/2), nên ngOnInit không chạy lại và trang hiện dữ liệu cũ. Vue cũng có bẫy này (cần watch(() => route.params.id)). Ở Angular, đọc id bằng input signal và dùng computed / httpResource sẽ tự chạy lại.

#Làm việc với DOM sau khi render

chart-box.ts
import { Component, ElementRef, afterNextRender, afterRenderEffect, inject, input, viewChild } from '@angular/core';

@Component({
  selector: 'app-chart-box',
  template: `<canvas #cv width="600" height="240"></canvas>`,
})
export class ChartBox {
  data = input.required<number[]>();
  private cv = viewChild.required<ElementRef<HTMLCanvasElement>>('cv');
  private chart?: ChartLib;

  constructor() {
    // Một lần, sau lần render đầu tiên: khởi tạo thư viện
    afterNextRender(() => {
      this.chart = new ChartLib(this.cv().nativeElement);
    });

    // Mỗi khi data đổi VÀ sau khi DOM đã cập nhật: vẽ lại
    afterRenderEffect(() => {
      this.chart?.draw(this.data());
    });
  }
}

afterNextRender và afterRenderEffect chỉ chạy trên trình duyệt, không chạy khi render phía server. Vì vậy đây là chỗ an toàn để dùng window, document, localStorage, đo kích thước (bài 20).

#Dọn dẹp: DestroyRef

TypeScript
import { DestroyRef, inject } from '@angular/core';

export class LiveClock {
  now = signal(new Date());

  constructor() {
    const id = setInterval(() => this.now.set(new Date()), 1000);
    inject(DestroyRef).onDestroy(() => clearInterval(id));
  }
}

DestroyRef dùng được cả trong service và hàm tiện ích (miễn là trong injection context), nên hay được dùng hơn ngOnDestroy. Những thứ Angular tự dọn cho bạn: effect, listener khai báo trong template / host, takeUntilDestroyed() (bài 14), toSignal().

Những thứ không tự dọn: setInterval, addEventListener gọi tay, WebSocket, subscribe() không có takeUntilDestroyed, instance của thư viện bên ngoài (bản đồ, biểu đồ, trình soạn thảo). Quên dọn → rò rỉ bộ nhớ và chạy ngầm sau khi rời trang.

#Thao tác DOM an toàn

TypeScript
private el = inject<ElementRef<HTMLElement>>(ElementRef);  // phần tử host của component / directive
private renderer = inject(Renderer2);
private doc = inject(DOCUMENT);                            // document, thay cho biến toàn cục

highlight() {
  this.renderer.addClass(this.el.nativeElement, 'flash');  // không chạm thẳng DOM
  this.doc.title = 'Đang chấm bài';
}

Thứ tự ưu tiên: binding trong template → host → Renderer2 → nativeElement trực tiếp (chỉ trong afterNextRender). Đi thẳng vào DOM khiến component khó chạy khi SSR và dễ xung đột với cách Angular cập nhật giao diện.

#Lifecycle hook kiểu cũ

TypeScript
export class OldComponent implements OnChanges, OnInit, AfterViewInit, OnDestroy {
  @Input() id!: number;
  private sub?: Subscription;

  ngOnChanges(changes: SimpleChanges) { if (changes['id']) this.load(); }
  ngOnInit() { this.sub = this.service.updates$.subscribe(...); }
  ngAfterViewInit() { this.input.nativeElement.focus(); }
  ngOnDestroy() { this.sub?.unsubscribe(); }
}

Ngoài ra còn ngDoCheck, ngAfterContentInit, ngAfterContentChecked, ngAfterViewChecked: hiếm khi cần. Nếu gặp ngDoCheck trong code cũ, thường đó là chỗ đang làm việc mà signals làm tốt hơn.

Câu hỏi nhanh. Component nhận id = input.required<number>(). Đọc this.id() trong constructor thì sao?

Input được gán sau khi class được tạo. Đọc trong ngOnInit, computed, effect hoặc template.

Câu hỏi nhanh. Khởi tạo thư viện bản đồ cần phần tử div đã có trong DOM. Đặt code ở đâu?

DOM chỉ tồn tại sau lần render đầu. afterNextRender còn không chạy khi SSR, tránh lỗi window không tồn tại.

#Bài tập

Đồng hồ đếm ngược hạn nộp

Viết component nhận input deadline (chuỗi ISO), hiển thị "còn X giờ Y phút Z giây", cập nhật mỗi giây, chuyển sang "Đã hết hạn" màu đỏ khi quá hạn. Đổi input sang hạn khác thì hiển thị cập nhật ngay. Không rò rỉ timer khi component bị gỡ.

Gợi ý từng bước

  1. now = signal(Date.now()), cập nhật bằng setInterval trong constructor, dọn bằng DestroyRef.
  2. remainMs = computed(() => Date.parse(this.deadline()) - this.now()): tự tính lại khi deadline hoặc now đổi.
  3. Định dạng giờ / phút / giây bằng Math.floor và padStart(2, '0').
  4. Ẩn / gỡ component để thử: bọc nơi dùng trong @if (show()) { ... }, kiểm tra trong DevTools rằng timer dừng.
Xem lời giải
countdown.ts
import { Component, DestroyRef, computed, inject, input, signal } from '@angular/core';

@Component({
  selector: 'app-countdown',
  host: { '[class.over]': 'remainMs() <= 0' },
  template: `
    @if (remainMs() > 0) {
      Còn {{ text() }}
    } @else {
      Đã hết hạn
    }
  `,
  styles: `:host { font-variant-numeric: tabular-nums; } :host(.over) { color: #dc2626; font-weight: 600; }`,
})
export class Countdown {
  deadline = input.required<string>();
  private now = signal(Date.now());
  protected remainMs = computed(() => Date.parse(this.deadline()) - this.now());
  protected text = computed(() => {
    const s = Math.floor(this.remainMs() / 1000);
    const h = Math.floor(s / 3600);
    const m = Math.floor((s % 3600) / 60);
    const sec = s % 60;
    const two = (n: number) => String(n).padStart(2, '0');
    return `${h} giờ ${two(m)} phút ${two(sec)} giây`;
  });

  constructor() {
    const id = setInterval(() => this.now.set(Date.now()), 1000);
    inject(DestroyRef).onDestroy(() => {
      clearInterval(id);
      console.log('countdown: đã dọn timer');
    });
  }
}

Giải thích: không cần ngOnChanges hay ngOnInit: remainMs đọc cả deadline() và now(), nên đổi hạn hay qua mỗi giây đều tự tính lại. Khi bỏ tích ô, khối @if gỡ component, DestroyRef chạy và timer dừng. Không dọn thì timer vẫn chạy mãi, mỗi lần bật lại tạo thêm một timer mới.
